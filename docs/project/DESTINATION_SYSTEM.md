# China Prime DMC V2 Destination System

## Destination Template

All destination pages are generated by `DestinationTemplate` from one CMS-shaped data object.

Route pattern:

- `/destinations/[slug]`
- Example: `/destinations/beijing`

Template order:

1. Hero
2. Quick Facts
3. Why Visit
4. Best Time to Visit
5. Top Highlights
6. Signature Experiences
7. Featured Luxury Hotels
8. Suggested Tours
9. Travel Inspiration Gallery
10. Travel Tips
11. FAQ
12. Inquiry CTA
13. Related Inspiration
14. Footer

## Destination Components

- `DestinationTemplate`: full page orchestration
- `HeroLargeImage`: immersive hero
- `StatisticCard`: quick facts and seasonal facts
- `EditorialLayout`: why visit storytelling
- `DestinationCard`: highlights and hotel cards
- `ExperienceCard`: reusable experience cards
- `TourCard`: related journey recommendations
- `GridGallery`: destination gallery
- `FeatureCard`: tips and seasonal notes
- `Accordion` via Radix UI: FAQ
- `CtaCard`: inquiry conversion
- `SiteNavigation`, `SiteFooter`, `FloatingCta`, `StickyMobileCta`

## CMS Field Mapping

| CMS Field          | Frontend Component                    |
| ------------------ | ------------------------------------- |
| `hero`             | `HeroLargeImage`                      |
| `quickFacts`       | `StatisticCard` grid                  |
| `whyVisit`         | `EditorialLayout` + `DestinationCard` |
| `bestTime.seasons` | `FeatureCard` grid                    |
| `highlights`       | `DestinationCard` grid                |
| `experiences`      | `ExperienceCard` grid                 |
| `hotels`           | optional `DestinationCard` grid       |
| `tours`            | `TourCard` grid                       |
| `gallery`          | `GridGallery`                         |
| `tips`             | `FeatureCard` grid                    |
| `faqs`             | FAQ accordion + FAQ JSON-LD           |
| `related.articles` | `BlogCard` grid                       |

## Content Relationship System

Destination relationships are designed to support both manual CMS priority and automatic fallback.

Current logic:

- If `related.journeys` is configured, render it.
- If not configured, fallback to the first three destination `tours`.
- If `related.experiences` is configured, render it.
- If not configured, fallback to the first three destination `experiences`.

Future CMS matching can add:

- destination slug tags
- route overlap
- travel style tags
- season tags
- manual priority
- conversion performance ranking

## SEO Architecture

Each destination page supports:

- dynamic Metadata API title
- dynamic meta description
- canonical URL
- Open Graph image
- Twitter Card
- `TouristDestination` JSON-LD
- FAQ JSON-LD
- Breadcrumb JSON-LD
- image alt text
- internal anchors and related links

## Responsive Rules

- Hero remains immersive on desktop and mobile.
- Quick facts compress from six columns to mobile cards.
- Highlights, tours, hotels, tips, and related content use the shared responsive grid.
- Sticky mobile CTA appears only after scroll and stays compact.
- Content is structured for scanning, not encyclopedia-style reading.

## Motion System

The destination system reuses existing motion-enabled components:

- media-card image zoom hover
- card lift hover
- smooth scroll
- glass navigation transitions
- accordion reveal through Radix state

No page-specific animation language is introduced.

## Sprint 6 Readiness

To add a new destination:

1. Add image assets to `content/destinations/assets.ts` or CMS media.
2. Add a `Destination` object in `content/destinations/index.ts` or CMS adapter.
3. Ensure `slug`, `hero`, `quickFacts`, `highlights`, `experiences`, `tours`, `gallery`, `tips`, and `faqs` are populated.
4. The `/destinations/[slug]` page will render automatically.
