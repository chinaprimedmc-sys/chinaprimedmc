## SEO 检查结果

### 发现、索引与 HTML

- 9 个 canonical ID 在 explorer、editorial、媒体、公开路由清单、搜索适配、站内搜索和 sitemap 中一致。
- 已发布目的地没有被旧重定向拦截；118 个字面量目的地源码链接指向已发布指南，不依赖旧地址兜底。
- 目录提供目的地入口；详情模板为 Server Component，规划正文不依赖客户端筛选后才取得。尚未完成本次生产 HTML 抓取验证。
- metadata 返回正确的独立 canonical，目的地 index/follow 开启。生产 HTTP 头、部署层 X-Robots-Tag、WAF/CDN 和真实 canonical 仍需另验。
- robots 的 allow `/` 已覆盖目的地；没有显式 `/destinations/` 不等于被屏蔽。`/api/` 被禁止。机器人允许访问也不保证其抓取或引用。
- sitemap 已有全部 9 篇。目的地未添加虚构的 lastModified；不应为了“新鲜度”把每次构建时间冒充内容更新时间。
- 元数据关键词字段不是当前应优先优化的增长因素，主要精力应放在正文意图、链接、可信信息和查询表现。

### 内容、长尾词与竞争

内容已经覆盖可直接影响出行决定的因素：完整游览日与晚数、酒店位置、机场和车站、步行/台阶、门票与排队、不同景区的区分、哪些选项适合增加一天。短答案在前、选择理由随后，利于读者和检索系统理解。

仍需区分“有长尾覆盖”与“长尾能带来流量”。例如 where to stay 类词可能由成熟旅游站和平台占据；城市 private tours 词也可能竞争激烈。更具体的条件组合适合做候选入口，但更长并不必然更容易、更有需求或更能转化。

上线后的关键词验证顺序：

1. 按目的地导出 28/90 天 query-page 数据，确定已有展示词、意图与目前着陆页。
2. 优先选有真实产品承接、规划问题具体、页面已出现相关展示的查询。
3. 核对目标市场的当前 SERP：结果类型、主要竞争页、答案形式、需要补足的独有信息。记录实际依据后再谈竞争压力。
4. 对比目的地、文章、产品是否回答同一购买阶段。多个页面有展示本身不构成有害蚕食；先看意图、排名稳定性、CTR 与转化。
5. 先精修已有页面里的答案和内链，再决定是否新增文章；不要批量生成只替换城市名的页面。

### 产品转化

每篇先给出目的地选择、停留天数和实际规划建议，再通过独立的选线说明进入精选产品比较。服务范围在产品比较处解释；首屏及示例行程后的按钮可直接跳到比较区，不再反复将所有读者导向首个产品。推荐顺序来自编辑选择，产品点击沿用 TrackedLink，询盘保留目的地上下文。

当前只是转化路径实现完整，尚不能判断实际转化率。上线后应按目的地观察：自然搜索着陆 → 产品点击 → 询盘开始 → 成功提交 → 合格询盘。点击跟踪的实际入库、归因和同意状态影响，仍须在分析平台验证；不要用页面链接数量代替商业成效。

## GEO 检查结果

### 已具备的基础

- 目的地名称、站点品牌、运营主体与指南出版方有明确来源，不将办公室所在城市误当作全部服务范围。
- WebPage 与 TouristDestination 通过稳定 ID 连接；BreadcrumbList、精选产品 ItemList 和 FAQPage 与对应内容使用同源数据。
- FAQ 的问题和答案直接用于页面与 markup，共 54 条；FAQ 结构化数据不代表旅游商业网站一定获得 Google FAQ 富结果。
- 答案能独立解释主要选择，避免只有宣传词；尤其保留“可选”“单独确认”“公共船/私享陆地服务”等约束，减少 AI 只提取卖点而误述包含项。
- 两个 AI 阅读文件现在都能找到全部 9 篇 canonical 指南、完整规划答案、服务范围和产品推荐理由；完整文件还复用细节与 FAQ，减少多处手工维护产生的冲突。
- JSON-LD 组件转义危险字符并使用请求 nonce；本次不是仅检查 script 标签是否存在。

### 仍需补强的证据

1. **规则来源离具体主张仍可更近。** 目的地正文目前主要通过专题文章承接官方规则与来源，缺少统一的逐项来源/核验日期字段。下一轮优先处理票务、交通、船运、景区开放和高海拔提醒；先核验真实官方来源，再把必要链接放到相应段落。政策链接不能替代规则证据。
2. **第一手经验需要可核实素材。** 如需突出运营优势，可补充获准发布的真实线路调整案例、具体酒店接送限制和带日期的现场记录。当前没有为提高所谓 E-E-A-T 编造作者资历或“亲测”故事。
3. **时间敏感信息需要维护责任。** 可为重点规则增加核验人、核验日期、来源与下一次复查记录。上线时间、编辑时间和供应商确认时间应分开，不能用同一天替代。
4. **AI 引用结果未实测。** 需要固定一组真实规划问题，在目标搜索/回答产品中记录回答日期、是否检索、引用 URL、服务包含项是否正确。个别回答波动很大，不能以单次提及宣称 GEO 成功。
5. **站外品牌与权威性未审计。** 真实媒体、商业目录、口碑和反向链接可能影响发现与信任，但本次没有足够数据评价；不建议靠堆 Schema 或扩充 llms 文件替代这些工作。

## 追加精修：英语规划表达与阅读递进

按用户要求进一步调整 9 篇的内容顺序和线路承接：

- 优先回答 Why visit、How many days、What to see、Sample itinerary、Getting there、Where to stay；以自然英语解释选择，不把一串关键词塞入标题。
- 保留晚数比较，但用完整游览日解释实际可用时间，避免“五日产品”等同于“五个完整游览日”。
- 文化、美食内容移至实用规划之后；保留目的地具体内容，删除重复的通用“推荐停留几晚”段落。
- 新增 9 段独立选线说明，区分已有机酒的单日需求、当地多日游和跨城市行程。乐山使用专门标题，不暗示存在已发布的独立乐山日游产品。
- 首屏与行程后的比较按钮跳到真实产品比较区；延伸目的地放在当前目的地产品之后。已准备好咨询的读者仍可直接开始规划。
- 询盘提示包含日期、抵离城市、步行需求和已订服务，让读者知道需要提供什么，以及将获得怎样的建议。
- 两个 AI 阅读文件同步复用选线建议，完整文件先输出规划细节、再解释服务与产品；自动审核验证选线建议没有遗漏。

这些用语遵循英语旅行规划中自然的提问方式，属于编辑判断。尚未使用欧美市场的当前关键词数据库或 SERP 数据验证搜索量、竞争难度与国家差异；不把美国、英国和其他欧洲市场视为完全相同的人群，也不声称英语页面覆盖非英语搜索需求。
